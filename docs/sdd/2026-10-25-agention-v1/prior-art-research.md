# Agention v1: Prior Art and Host Research

- Date: 2026-10-25; host research extended 2026-10-27; asks, threads, filters and folding researched
  2026-10-30
- Method: web research against primary sources where available; unverified points are marked.

## Executive summary

Among the systems reviewed, none separates what is asked of a human from how it affects the work.
JMAP comes closest to pairing per-user read state with state-checked writes, but not on a shared,
attributed log. The pieces exist separately: A2A and MCP Tasks model task state, MCP elicitation
models structured responses, GitHub and Linear separate action from awareness, Matrix separates read
receipts from "caught up", and JMAP and event stores provide state-checked writes. Agention combines
them under an honor-system trust model. The agent hosts' question tools have converged on one shape,
a question with suggested answers and the person's own words, and mail clients keep read and archive
state on messages and present views as filters; Agention's threads, asks and thread list follow
both. Host research settles tool naming and shaped the agent bridge: neither host's built-in MCP
client can carry an approval flow that suits agents, and both hosts run a pinned `npx` stdio server
declared by a plugin.

## Pitfalls considered

- **Stale-write starvation.** A frequently posting agent could repeatedly fail a typing human. With
  one human and occasional agent writes this is unlikely. The stale response carries the missed
  entries and the UI keeps the draft. The operator's rule (every write is stale-checked) is kept;
  exempting plain comments was considered and rejected because it reintroduces racing updates.
- **Wake-up.** MCP gives no reliable push to command-line agents. Agents long-poll, bounded below
  host tool timeouts.
- **Session handles are names, not capabilities.** Every call checks the stated session against the
  credential's grants.

## Refuted or do-not-rely-on

- Dots in tool names are safe because the MCP specification allows them: hosts and the Anthropic API
  do not accept them uniformly.
- A plugin can ship the MCP server entry with environment-derived session headers: not documented.
- Custom headers coexist with Claude Code native OAuth: plausible but not documented.
- Hosts store OAuth tokens per server entry name: Claude Code documents per-endpoint storage
  instead.
- Cursor's and OpenCode's question tools in detail: only community posts and a mirror of OpenCode's
  tool were read.
- Outlook's prompt to send a vote at once or edit it first: described by one source, for
  Outlook 2010.
- Outlook on phones filtering by mentions: its mobile filters are unread, flagged and attachments.
- A product ordering groups by their most urgent item: none found; Agention's group order is its own
  rule.
- Slack showing a count on, or unread conversations inside, a collapsed section: one blog says so;
  Slack's help is silent.
